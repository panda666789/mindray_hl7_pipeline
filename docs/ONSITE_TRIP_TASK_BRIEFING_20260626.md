
## 3. 你需要了解的基础概念

### 3.1 无感体征采集是什么

这里的“无感”通常指不接触人体或尽量少接触，通过摄像头视频、红外视频、环境传感器等方式估计生命体征。

常见目标：

- 心率 HR
- 呼吸 RR
- 血氧 SpO2，难度通常更高
- 血压 BP，通常需要额外模型、校准或参考测量，不要轻易承诺“直接准确测血压”

今天最重要的不是证明算法已经完美，而是确认采集流程能稳定产生可用于分析的数据。

### 3.2 为什么要确认 30 fps

视频帧率决定了时间采样密度。无感心率通常要从视频里提取微弱周期信号，如果帧率不稳定或低于预期，会影响心率估计、频谱分析和后续对齐。

现场不要只问“设置是不是 30 fps”，要尽量拿到证据：

- 软件设置截图显示 30 fps。
- 导出视频文件属性显示约 30 fps。
- 如果电脑有 `ffprobe`，用命令确认实际帧率。
- 如果没有工具，至少记录视频时长、帧数或播放器属性截图。

有条件时用：

```powershell
ffprobe -v error -select_streams v:0 -show_entries stream=avg_frame_rate,r_frame_rate,duration,nb_frames -of default=nw=1 "视频文件路径.mp4"
```

重点看：

```text
avg_frame_rate=30/1
r_frame_rate=30/1
```

如果不是严格 30，也要记录实际值，比如 29.97 fps。

### 3.3 RGB 和红外分别看什么

RGB 视频看可见光画面质量：

- 人脸/胸部/目标区域是否清楚。
- 有没有过曝、欠曝、强反光。
- 运动模糊是否严重。
- ROI 区域有没有被遮挡。

红外视频看弱光或夜间可用性：

- 红外画面是否有足够对比度。
- 是否过曝成一片白，或太暗看不清。
- 红外补光是否稳定。
- RGB 和红外时间是否一致。

判断口径：

```text
不是“画面能打开”就够了，而是画面要稳定、清晰、能支撑后续提取周期性生理信号。
```

### 3.4 时间同步到底同步什么

今天至少有三类时间：

1. 采集软件里的时间戳。
2. 迈瑞监护仪导出数据里的时间。
3. 人工记录的关键任务时间，比如开始采集、测血压、喂奶、安静状态、哭闹、移动等。

你要确认的是这些时间能不能对齐。

最低要求：

- 采集电脑/手机/监护仪的系统时间尽量一致。
- 所有设备都在中国时区 UTC+8 / Asia/Shanghai。
- 开始采集和结束采集时，人工记录真实时间。
- 每个关键任务记录精确到秒，至少精确到分钟。
- 导出数据后能找到对应时间窗。

现场可以记录：

```text
09:13:20 开始无感视频采集
09:14:05 开始监护仪数据记录
09:15:00 第一次血压测量
09:16:30 婴儿明显移动/哭闹
09:18:00 结束本段采集
```

如果有条件，可以做一个“同步动作”：

- 在摄像头画面里展示手机秒表。
- 或在开始采集时做一个明显动作/标记。
- 或让所有设备画面/系统时间同屏拍照。

## 4. 任务 A：确认无感体征采集流程

截图里的任务要求：

1. 确认视频帧的帧率为 30 fps，红外和 RGB 成像质量没有问题。
2. 确认波形数据的同步性，以及采样点、血压等关键任务的时间戳一致。
3. 可视化一部分数据。
4. 产出简要的数据报告。

### 4.1 到现场先问

联系王辰元后，先问清楚：

1. 今天用哪套无感采集设备？
2. RGB 和红外是一个设备还是两个设备？
3. 视频保存在哪台电脑/手机？
4. 输出格式是什么：mp4、avi、图片序列、csv、数据库？
5. 采集软件是否会写每帧时间戳？
6. 关键任务有哪些：血压、采样点、安静/活动、喂奶、睡眠、哭闹？
7. 谁负责在现场标记关键任务时间？

### 4.2 帧率确认

要拿到这些证据之一：

- 采集软件设置页截图：30 fps。
- 导出视频文件属性截图：帧率接近 30 fps。
- `ffprobe` 输出。
- 软件日志里每帧时间戳间隔接近 33.3 ms。

如果帧率不是 30 fps，不要现场拍脑袋改算法。先记录：

```text
设置帧率：
实际导出帧率：
是否稳定：
是否丢帧：
可能原因：
```

### 4.3 画质确认

现场至少保存 3 类截图：

1. RGB 正常画面。
2. 红外正常画面。
3. 采集时目标区域截图。

看图时重点：

- ROI 是否在画面里。
- 目标区域是否稳定。
- 光照是否稳定。
- 有没有明显遮挡。
- 婴儿移动时画面是否完全不可用。

### 4.4 同步性确认

你要把这些时间放在同一张表里：

| 事件 | 人工记录时间 | 采集软件时间 | 监护仪/CMS 时间 | 备注 |
| --- | --- | --- | --- | --- |
| 开始采集 |  |  |  |  |
| 开始监护仪记录 |  |  |  |  |
| 血压测量 |  |  |  |  |
| 采样点/任务点 1 |  |  |  |  |
| 结束采集 |  |  |  |  |

判断：

- 如果误差在几秒内，通常可以先接受并记录。
- 如果误差达到分钟级，必须查时区、系统时间、设备时间。
- 如果只有相对时间，没有绝对时间，也要记录“从开始采集后第几秒”。

### 4.5 可视化一部分数据

最低可视化目标：

- 选 1 段 1 到 3 分钟数据。
- 画出至少一条趋势或波形。
- 标出关键任务时间点。

可视化不必现场做得很漂亮，但要能回答：

```text
这段数据对应哪个人/设备/时间窗？
这段里 RGB/红外是否可用？
这段里监护仪或采集软件有没有对应数据？
关键任务时间点能否落在图上？
```

### 5.2 更新后必须验证

1. 打开手机系统时间页面，拍照或截图。

1. 手机系统时区是否是中国标准时间。

4. 后端或导出工具是否二次转换了时区。
5. 是否需要重新登录、清缓存或重启 App。

## 6. 任务 C：迈瑞监护仪导出和 CMS Viewer 查看

截图里的任务要求：

1. 携带 U 盘，导出迈瑞的数据。
2. 携带 Windows 电脑，安装指定 CMS Viewer 软件进行数据查看，确认是否有对应时间窗的数据。
3. 对更新后的软件拍照，对导出的数据进行可视化，产出初步报告。

### 6.1 你要带

- U 盘，最好空盘或至少有足够空间。
- Windows 电脑。
- 指定 CMS Viewer 安装包。
- 项目交付包。
- Python 安装包，防止现场电脑没环境。
- 纸笔或表格，用来记录时间点。

### 6.2 导出前先问

问孙老师或医院工程师：

1. 迈瑞监护仪型号是什么？
2. 导出菜单在哪里？
3. 能导出哪些类型：波形、趋势、报警、事件、报告？
4. 导出的时间范围怎么选？
5. 导出文件能否离开医院电脑？
6. CMS Viewer 版本是否和设备导出格式匹配？
7. 是否有数据使用和拷贝授权？

### 6.3 U 盘导出时记录

每次导出都记录：

```text
导出时间：
监护仪型号：
监护仪床位/设备标识：
导出时间窗：
导出类型：
U 盘路径：
文件名：
文件大小：
是否能在 CMS Viewer 打开：
```

不要只看“导出成功”，要确认导出的时间窗覆盖今天采集段。

### 6.4 CMS Viewer 查看

Windows 上安装或打开指定 CMS Viewer 后，重点看：

- 能否打开 U 盘导出文件。
- 是否能选择对应时间窗。
- 是否有 ECG、PLETH、RESP 等波形。
- 是否有 HR、SpO2、RR、血压等趋势或数值。
- 时间轴是否和人工记录时间一致。

建议截图：

1. CMS Viewer 打开文件成功的界面。
2. 对应时间窗的波形界面。
3. 趋势/生命体征界面。
4. 软件版本或关于页面。

### 6.5 和本项目 HL7 采集的区别

你今天可能会遇到两条迈瑞数据路线：

| 路线 | 来源 | 用途 |
| --- | --- | --- |
| U 盘导出 + CMS Viewer | 监护仪内部存储导出 | 回看历史、确认时间窗、做人工核验 |
| HL7 实时采集 | 监护仪通过网络发给 Windows 采集端 | 实时落盘、生成 raw_hl7 / waveform_csv / numerics_csv |

两者不是一回事。U 盘导出能帮助核验监护仪原始记录，但不等于 HL7 实时链路已经通了。HL7 实时链路仍要看采集端窗口和本地 `data` 目录。

## 8. 今天不要踩的坑

1. 不要只截图界面，要记录文件名、时间窗、设备号。
2. 不要只问“是不是 30 fps”，要拿实际证据。
3. 不要把 `numerics_csv` 或报警事件当成必然出现；要看监护仪是否发送对应报文。

5. 不要未经允许把婴儿数据、监护仪数据、截图发到个人网盘或聊天软件。
